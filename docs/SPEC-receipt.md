# 附录 R：报告页的小票导出

版本 0.1，2026-10-14
状态：可以开始开发
所属：`docs/SPEC.md` 的"报告与导出"一节。本附录与 SPEC 冲突时，以 SPEC 的设计原则（估算透明、完全本地、不用 emoji、遵循 HIG）为准。

---

## R1. 概述

在操作台的"报告"页增加一种导出样式：仿真实热敏小票的用量账单。它和现有的 PNG 分享卡片并存，不替代任何已有格式。

小票有三个输出目标，共用同一个 SwiftUI 视图 `ReceiptView`：

| 输出 | 用途 | 里程碑 |
|---|---|---|
| 屏幕预览 | 导出前在操作台里查看和调整 | M5 |
| PNG | 复制到剪贴板或存储，发社交平台 | M5 |
| 打印 | 通过系统打印或直连热敏打印机打出实体小票 | 系统打印 M5；直连 M9 |

和同类项目的区别：同类小票只列 token 和美元。本产品的小票列的是 token、估算电量、CO₂ 和日常等效（以"微波炉转了几次"为固定项），不显示美元（见 SPEC 1.2）。

## R2. 入口与交互

### R2.1 入口

报告页工具栏的"导出"菜单新增两项：

- 小票图片…
- 打印小票…

两项都打开同一个预览面板（sheet），只是默认焦点按钮不同。

### R2.2 预览面板

左侧是小票预览，按实际比例显示，可滚动。右侧是选项：

| 选项 | 取值 | 默认 |
|---|---|---|
| 周期 | 跟随报告页当前选择（日 / 周 / 月 / 年） | 当前选择 |
| 纸宽 | 80 mm / 58 mm | 80 mm |
| 纸张效果（仅 PNG） | 开 / 关 | 开 |
| 显示二维码 | 开 / 关 | 开 |
| 隐藏项目名 | 跟随导出设置 | 跟随 |
| 抬头署名 | 空，或用户输入的昵称（最多 16 个字符） | 空 |

底部按钮：拷贝图片、存储…、打印…。

### R2.3 设置

"设置 > 导出"增加"小票"分组：

- 默认纸宽
- 打印方式：系统打印机 / 网络热敏打印机（ESC/POS） / 不打印
- 网络打印机地址：`主机:端口`，端口默认 9100，带"测试打印"按钮
- 每日结束时自动打印当日小票：默认关闭。开启时沿用 SPEC 中自动生成日报的触发时机

### R2.4 文件名

`AIE-receipt-<起始日期>-<周期>.png`，例如 `AIE-receipt-2026-10-14-daily.png`。产品改名时与 SPEC 第 2 节的可替换标识一起修改。

## R3. 版式

### R3.1 尺寸与网格

小票按真实热敏纸的点阵设计，所有尺寸以"点"（dot，203 dpi）为单位，屏幕和打印共用一套数字。

| 纸宽 | 可打印宽度 | 点数 | 每行字符列数 |
|---|---|---|---|
| 80 mm | 72 mm | 576 | 48 |
| 58 mm | 48 mm | 384 | 32 |

48 列和 32 列对应 Epson TM 系列默认字体（12×24 点）在两种纸宽上的列数，这样屏幕上的排版和真实打印机打出来的一致。

布局以字符列为单位。一个英文字符或数字占 1 列，一个中文字符占 2 列。每个表格单元格用 `.frame(width: 列数 × 单列宽度)` 固定宽度，不要用空格补齐对齐（原因见 R4）。

PNG 导出时，逻辑宽度等于点数（80 mm 为 576），用 `ImageRenderer` 以 scale 2 渲染，得到 1152 像素宽的图片。

### R3.2 结构

从上到下依次为：

1. **抬头**：Logo（R5）、产品名、副标题"本机 AI 用电小票 / AI POWER RECEIPT"。如果填了署名，加一行"顾客 / FOR"。
2. **单据信息**：单号、周期类型、统计时段、打印时间、时区、"收银员"一行显示应用版本号（例如 `收银员  aie 0.1`）。
3. **明细**：按工具分组，组内每个模型一行，列为：模型名 / Tokens / 电量 Wh。最多显示 8 行，其余合并为"其他 N 项"。模型名超长时截断并加省略号。
4. **Token 构成**：输入、输出、缓存写入、缓存读取四个数字，下面一条按比例分段的横条（R3.4）。注明缓存读取的耗电权重较低，与 SPEC 的计算方法一致。
5. **电量与 CO₂**：电量小计、估算区间、CO₂ 克数、碳强度口径（电网平均 / 实时电网）。M7 完成后增加洁净度一行；M7 之前不显示这一行，不显示占位。
6. **相当于**：等效换算，规则见 R6。
7. **合计**：双线分隔，"合计"一行用倍高字号显示电量总数，下一行显示 CO₂ 总数。
8. **页脚**：一行声明"本单据为估算值，不作报销凭证"；一行"计算方法见 设置 > 关于 > 方法说明"；二维码（指向项目仓库地址，地址放在可替换标识里）；单号的条形码；最后一行"谢谢惠顾 / THANK YOU"。

周报、月报额外在第 5 节和第 6 节之间加一个"每日用电"小柱状图（R3.4）。年度总结的小票只列 12 个月的柱状图和全年合计，不列每个模型的明细，避免小票过长。

### R3.3 示意（80 mm，48 列，数字为虚构）

```
                  [ LOGO ]
                AI ELECTRICITY
               本机 AI 用电小票
------------------------------------------------
单号   2026-1014-0003                      日报
时段   2026-10-14 00:00–23:59          AEST
打印   2026-10-14 23:58
收银员 aie 0.1
------------------------------------------------
项目                        Tokens      电量 Wh
------------------------------------------------
Claude Code
  opus                       1.82M         18.9
  haiku                      0.41M          1.2
Codex
  gpt-5-codex                0.61M          3.5
------------------------------------------------
Token 构成
  输入     0.21M        输出     0.09M
  缓存写   0.34M        缓存读   2.20M
  [####====::::::::::::::::::::::::::::::::]
------------------------------------------------
电量小计                                23.6 Wh
  估算区间                           12–41 Wh
CO2                                     9.4 g
  口径                               电网平均
------------------------------------------------
相当于
  微波炉转了                             1.4 次
  手机充满                               1.6 次
  吃下一根香蕉的热量                     0.2 根
================================================
合计                                 23.6 Wh
                                       9.4 g CO2
================================================
     本单据为估算值，不作报销凭证
  计算方法见 设置 > 关于 > 方法说明

                  [ QR ]
            | ||| || |||| | |||
            2026-1014-0003
                 谢谢惠顾
```

示意中的 `#`、`=`、`:` 只代表横条的分段，实际用矩形绘制（R3.4）。"合计"一行在实际渲染中为倍高字号。

### R3.4 分隔线与图形

- 普通分隔：一整行短横线 `-`，用字体绘制。
- 合计上下：一整行 `=`。
- Token 构成横条、每日柱状图：用 SwiftUI 的 `Rectangle` 绘制，宽度按列对齐，不要用方块字符（▁▂▃█ 等），因为 SF Mono 不一定包含这些字形，打印时也会失真。
- 横条分段只用纯黑、斜线填充、点状填充、白底四种图案区分，不用灰色。原因：打印时要转成 1 位黑白图（R7.3），灰色会消失或变成噪点。

### R3.5 纸张效果（仅 PNG）

开启时：纸色 `#FBFAF7`，上下两端为锯齿撕边（齿宽 8 点，齿高 4 点），四周留 32 点透明边距并加一层很淡的投影。关闭时：纯白底、直边、无投影。

不加噪点、褶皱、污渍这类纹理。

打印输出永远是纯白底黑字，不带任何纸张效果。

### R3.6 外观模式

小票本身始终是白纸黑字，不随系统深色模式变化。预览面板的其他部分跟随系统外观。

## R4. 字体

小票全部使用等宽代码字体。

- 拉丁字母、数字、符号：`Font.system(size:weight:design: .monospaced)`，即系统自带的 SF Mono。这是系统字体，不需要打包，也没有授权问题。数字统一用 `.monospacedDigit()`。
- 中文：SF Mono 不含中文，系统会自动回退到苹方。苹方的中文字宽不一定正好是 SF Mono 一个字符宽度的 2 倍，所以对齐必须靠 R3.1 的固定宽度单元格，不能靠空格补齐。
- 字号：正文 22 点高（约等于打印机 12×24 字体），小字 18 点，合计行倍高 44 点。
- 字重：正文 Regular，抬头产品名和合计行 Bold。

可选方案（如果需要中英文严格 2:1 的字符网格）：打包更纱黑体等宽版 Sarasa Mono SC（SIL OFL 1.1）。代价是安装包增加十几 MB。默认不采用，如改用需在 `docs/DECISIONS.md` 记录，并在 THIRD_PARTY_NOTICES 中加入 OFL 声明。

## R5. Logo

小票抬头使用应用自己的 Logo，黑白、简单。

### R5.1 资源要求

- 资源名 `ReceiptLogo`，矢量 PDF，放在 Asset Catalog，勾选 Preserve Vector Data。
- 只有纯黑一种颜色，背景透明。不能有渐变、灰色或半透明。
- 最细线宽不小于 3 点（约 0.38 mm），否则热敏打印会断线。
- 显示尺寸：80 mm 纸为 96×96 点，58 mm 纸为 72×72 点，水平居中。
- 和应用图标、菜单栏图标是同一个图形的单色版本。

### R5.2 占位方案

正式 Logo 设计完成前，用占位图形：一个 4 点线宽的圆角方框，里面是 Phosphor Icons 的 `lightning`（Bold）图标。Phosphor 已是项目的图标库（MIT），不需要新增依赖。

正式 Logo 交付后只替换 `ReceiptLogo` 资源，代码不改。

### R5.3 禁止

小票上不出现 Anthropic、Claude、OpenAI、Codex 的 Logo 或任何图形标志。工具名和模型名只以纯文字出现在明细里。

## R6. 等效换算

沿用 SPEC 中的 `equivalents.json` 和选择规则，增加小票专用的两点。

### R6.1 微波炉为固定项

"微波炉转了几次"永远是"相当于"一节的第一行。1 次的定义是：功率约 1000 W 的微波炉加热 1 分钟，约 17 Wh。

`equivalents.json` 中微波炉条目增加字段 `"receiptAnchor": true`。如果没有任何条目带这个字段，回退到 SPEC 的普通选择规则，不报错。

### R6.2 另外两项

从剩余条目中按 SPEC 的规则（让数字落在 1 到 100 之间）挑选，优先一个电器类、一个食物类。如果挑出了食物类，页脚声明下方加一行小字："食物项比较的是热量本身"。

### R6.3 数字格式

| 数值 | 显示 |
|---|---|
| 小于 0.1 | `< 0.1` |
| 0.1 到 10 | 一位小数，例如 `1.4` |
| 10 到 9,999 | 整数，例如 `236` |
| 10,000 及以上 | 中文 `1.2 万`，英文 `12k` |

### R6.4 文案

每项的小票文案放在 `equivalents.json` 的 `receiptLabel` 字段，中英文各一份，含数字占位符。例如：

```json
{
  "id": "microwave-1min",
  "category": "appliance",
  "wh": 17,
  "receiptAnchor": true,
  "receiptLabel": {
    "zh": "微波炉转了 %@ 次",
    "en": "Microwave runs: %@"
  }
}
```

在小票中，文案部分左对齐，数字部分右对齐，单位跟在数字后面。

## R7. 打印

### R7.1 系统打印（M5）

通过 `NSPrintOperation` 打印，适用于任何在"系统设置 > 打印机与扫描仪"中装好驱动的小票打印机，也适用于普通打印机。

- `NSPrintInfo.paperSize` 宽度为所选纸宽，高度等于小票内容高度。
- 四边页边距设为 0，关闭自动缩放和居中。
- 打印内容是 `ReceiptView` 以 scale 1 渲染出的位图，不是文字。

### R7.2 直连网络热敏打印机（M9）

通过 ESC/POS 协议直接发给网络打印机，不经过系统驱动。参考实现见 claude-receipts（R8）。

- 用 Network.framework 的 `NWConnection` 建立 TCP 连接，地址取自设置，默认端口 9100，连接超时 5 秒。
- 指令顺序：`ESC @` 初始化 → `GS v 0` 光栅位图（分段发送，每段不超过 256 行）→ 走纸 3 行 → `GS V 66 0` 切纸。
- 以 Epson TM-T88V 为基准测试机型。其他机型不保证，`docs/DECISIONS.md` 记录实际测试过的型号。
- 失败时在预览面板内显示具体原因（连接超时、拒绝连接、发送中断），不弹系统警告框。
- 如果应用开启了 App Sandbox，需要 `com.apple.security.network.client` 权限。

USB 直连不在范围内。USB 打印机请用 R7.1 的系统打印。

### R7.3 黑白转换

打印前把位图转成 1 位黑白：亮度小于 128 为黑，其余为白。不做抖动。因为 R3.4 和 R5.1 已禁止灰色，阈值法就足够了。

预览面板提供"打印效果预览"开关，开启时把预览显示为转换后的黑白图，方便检查。

## R9. 隐私

- 小票上不出现用户名、电脑名、完整路径和地理位置。时区只显示缩写。
- 开启"隐藏项目名"时，明细中只按工具和模型分组，不出现项目名。
- 署名只使用用户在预览面板里主动输入的文字，默认为空。
- 二维码只编码仓库地址，不编码任何用量数据。

---

## R10. 本地化

- 中英文两套文案，跟随应用语言，不跟随系统语言以外的任何设置。
- 英文版同样是 48 列（或 32 列）网格，列宽分配可以不同，在 `ReceiptLayout` 里按语言各定义一套。
- 数字的千位分隔符和小数点跟随当前语言区域。

---

## R11. 测试

在 SPEC 第 14 节的测试之外增加：

- 等效：微波炉固定为第一项；没有 `receiptAnchor` 时的回退；R6.3 每个区间的边界值。
- 明细：0 行（当天没有用量，小票仍能生成，各数字为 0，"相当于"一节显示"今天还没有用电"）、8 行、9 行（出现"其他 1 项"）、超长模型名截断。
- 版式快照测试：80 mm 和 58 mm、中文和英文、日 / 周 / 月 / 年，共 16 张参考图，放在 `Tests/.../Snapshots/Receipt/`。
- 对齐：中英文混排行的右侧数字列在快照中竖直对齐。
- 黑白转换：转换后的位图只含纯黑和纯白两种像素。
- ESC/POS：生成的字节流以 `ESC @` 开头、以切纸指令结尾，光栅段的长宽字段与位图尺寸一致。用本地 TCP 假服务器接收并校验，不依赖真实打印机。
- 隐私：开启"隐藏项目名"时，渲染出的文字中不含任何项目名。
